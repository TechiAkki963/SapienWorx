# P2.7 UI / Mockup Contract

P2.7 is a design-contract review programme, not a blanket redesign.

## Implementation boundary

Only recruiter screens belonging to the current P2.6 functional workstream may receive implementation changes:

- Dashboard
- Candidate discovery/search
- Talent CRM / pools
- Job Management
- Interviews
- Offers
- Outreach sequences/templates
- Saved searches/alerts
- Referrals
- Analytics

Candidate and Master Admin are reviewed in parallel as reference systems but are not restyled during P2.7 unless their backend/functionality becomes part of the active workstream.

## Brand contract

- Primary brand/action color: Meta / Royal Blue (`#0866ff`).
- Primary dark ink: navy (`#071d49`).
- Product surfaces remain clean, light and table/card-first rather than decorative.
- Source Serif 4 is the approved display/editorial face for recruiter product page titles.
- The current repository does not contain a reviewed Source Serif 4 font asset. Product CSS therefore declares Source Serif 4 first and uses Georgia / Times New Roman as resilient local fallbacks. Do not add a remote runtime font dependency or commit an unreviewed font file.
- Sans-serif remains the functional UI face for tables, controls, metadata and dense operational content.
- The approved woodpecker mascot is selective: welcome, AI/search assistance, success, empty/help/notification states only. Do not insert a mascot into dense tables, forms or analytics purely as decoration.
- Do not add decorative human photography to authenticated product workspaces. User/company profile media is functional content and is not considered decorative imagery.

## Role-specific review

### Recruiter

Compact operating workspace, clear page hierarchy, scan-first tables/cards, bottom navigation on tablet/mobile, high information density without clutter. P2.7 implements the shared recruiter product-header contract here.

### Candidate

Review-only in P2.7. Candidate UI may be warmer and guidance-oriented, but should preserve clean task hierarchy and the existing System/Light/Dark contract.

### Master Admin

Review-only in P2.7. Command Centre remains denser and governance-oriented. Fraud/risk intelligence stays Master Admin-only and must not leak into recruiter/candidate visual concepts.

## Mockup-to-backend rule

A mockup may show a state, action, KPI, filter or status only when the corresponding backend contract exists in the active functional workstream. Future-state ideas belong in design notes, not implemented UI.

## P2.7 acceptance evidence

The visual gate must:

1. render every active P2.6 recruiter area with the shared visual contract;
2. verify no horizontal overflow on representative laptop/tablet/mobile widths;
3. verify the display-title font contract;
4. verify product pages do not introduce decorative `/images/people/` imagery;
5. capture recruiter Light/Dark/System references;
6. capture Candidate and Master Admin reference screenshots for review only;
7. retain screenshots as CI artifacts.
