# SapienWorx Security Release Checklist

## Authentication and session

- [ ] Passwords are never logged or stored in plaintext.
- [ ] Access and refresh tokens use runtime secrets only.
- [ ] Expired, malformed and tampered JWTs are rejected.
- [ ] Logout invalidates/clears all relevant session state.
- [ ] OTP resend and verification are rate limited.
- [ ] Production cookies use `Secure`, `HttpOnly` and appropriate `SameSite` settings.

## Authorization / RBAC

- [ ] Candidate tokens cannot call recruiter endpoints.
- [ ] Recruiter tokens cannot call master-admin endpoints.
- [ ] Authorization is enforced server-side for every protected resource.
- [ ] Object ownership is validated to prevent IDOR/BOLA.
- [ ] Admin-only routes do not disclose sensitive data to unauthorized users.

## Input and API hardening

- [ ] Malformed JSON returns 400 without stack traces.
- [ ] Missing/invalid fields return deterministic validation errors.
- [ ] SQL injection payloads never alter schema/data and never cause 5xx responses.
- [ ] User content is rendered without executable HTML/script injection.
- [ ] Unsupported methods return 405/404 consistently.
- [ ] Request body limits are enforced.
- [ ] CORS allows only approved origins.

## Documents / S3

- [ ] CV objects are private by default.
- [ ] Direct public S3/MinIO object access is denied.
- [ ] Downloads use short-lived signed URLs.
- [ ] Signed URLs expire as configured and cannot be reused beyond expiry.
- [ ] Upload content type, size and extension rules are enforced server-side.
- [ ] Object keys are generated by the server and cannot escape expected prefixes.

## Integration isolation

- [ ] AWS SNS is the only permitted SMS transport.
- [ ] No Twilio, Google Auth, Google/Teams meeting SDKs, external AI APIs, SendGrid, Firebase/Auth0/Clerk or similar SaaS integration is present.
- [ ] Interview meeting URLs are treated as user-provided data only.
- [ ] Third-party isolation scanner passes in CI.

## Data / privacy / audit

- [ ] Candidate PII is not exposed in logs.
- [ ] Sensitive administrative changes produce audit records.
- [ ] Delete/retention behavior preserves relational integrity.
- [ ] Backups/restores are tested using non-production data.
- [ ] Production secrets are absent from Git history and build artifacts.

## Release blocker policy

Any exploitable auth bypass, BOLA/IDOR, SQL injection, stored/reflected XSS, public CV exposure, committed secret, forbidden third-party integration, or privilege escalation blocks release regardless of schedule.
